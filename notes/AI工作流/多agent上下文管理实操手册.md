# 多 Agent 上下文管理实操手册（纯手动版）

> 写给：snooze26h。工具现状：Claude Code（主力，带技能/MCP）、Codex CLI（经 codexcomp）、Gemini CLI、Grok CLI、web ChatGPT。
> 本手册**不依赖任何技能、不依赖任何脚本**，每一步都是你手动操作。案例领域：agent memory / 图结构记忆。
> 思想来源：《AI科研不完全指北》（Context Is All You Need）+ ChatGPT 详解版的修正，结合你的实际装机翻译成可操作步骤。

## 第一部分：上下文系统到底是什么（先建立正确的物理直觉）

### 1.1 三句话说清本质

1. **模型没有"记忆"，只有"当前视野"。** 每次你发消息，模型看到的全部世界 =（系统提示 + 自动加载的文件 + 这个会话里的全部历史消息和工具输出）。窗口有限（约 20 万 token 量级），塞满了就开始压缩/丢失。
2. **会话是易失的，文件是持久的。** 关掉会话，里面的一切就没了；写进磁盘的 markdown，任何工具、任何时候都能读。所以：**上下文管理 = 决定"什么进会话"（少而准）+ "什么进文件"（多而全）**。
3. **"多 agent"的本质不是模型多，而是"互相看不见的视野"多。** 同一个模型开两个新会话，它们互相不知道对方说过什么——这就是隔离。隔离的价值：评审者不被其他候选带偏、发散者不被历史否决束缚、主会话不被安装日志污染。

### 1.2 一个量级直觉（为什么污染这么致命）

- 一篇 40 页论文 PDF ≈ 3–5 万 token（占掉窗口 1/5）
- 一次 pip 报错全文 ≈ 几千到上万 token
- 一次完整训练日志 ≈ 轻松几十万 token（一次就撑爆）

更致命的不是"长"，而是**模型分不清哪些信息还有效**：旧计划和新计划并存、被证伪的假设还留在历史里、十几个补丁不知道哪个对应哪个现象。这时模型开始"沿着错误自洽"，表现为智力骤降、反复犯同一个错。**AI 修不好 bug，往往不是不会，是上下文坏了。** 判断标准：与其救一个坏会话，不如交接后新开一个。

### 1.3 你的五个工具，各自的上下文机制（事实表）

| 工具 | 开新会话时自动进入视野的东西 | 隔离手段 | 落盘能力 |
|---|---|---|---|
| **Claude Code** | `~/.claude/CLAUDE.md`（全局规则）+ 当前目录及上层的 `CLAUDE.md`（项目规则）+ 长期记忆索引 | 新开终端（走启动器）；`/clear`（原地清空重来）；**子代理**（派出去干活，只回结论） | ✅ 全套（读写文件、跑命令、MCP 搜索） |
| **Codex CLI** | `~/.codex/AGENTS.md` + 项目目录 `AGENTS.md` | 新会话 | ✅ 读写文件、跑命令 |
| **Gemini CLI** | 项目目录 `GEMINI.md` | 新会话 | ✅ 读写文件；搜索强 |
| **Grok CLI** | 约定不统一——**以开场手动粘贴规则为准** | 新会话 | 视配置 |
| **web ChatGPT** | 什么都不自动进（它读不到你的磁盘） | 天然隔离（每个新对话都是白纸） | ❌ 只能靠你粘进去/拷出来 |

**关键推论**：`CLAUDE.md` / `AGENTS.md` / `GEMINI.md` 是三家 CLI 的"开机自动注入通道"。让这三个文件都只写一句话——"规则见 PROJECT_RULES.md，状态见 PROJECT_STATE.md"——三家就共享同一份真源。web ChatGPT 和 Grok 靠你开场手动粘。**文件系统就是所有 agent 的共享总线**，没有更多魔法。

### 1.4 Claude Code 里的四个手动隔离动作（日常最常用）

1. **新会话**：双击 CC 启动器（红线不变）→ `cd 项目目录` → 说开工语（见附录 B）。最干净。
2. **`/clear`**：当前窗口原地清空，自动加载的文件会重新生效。等价于新会话。
3. **子代理**：对我说"**开一个子代理去做 X（装环境/大范围搜代码/读这堆日志），只把结论带回来**"。子代理在独立上下文里干脏活，主会话只进五行结论。这是把 L3 噪声挡在门外的主要武器。
4. **不粘大日志**：报错时不要把几百行日志粘进对话——存成文件，告诉我路径，我自己选择性读（或派子代理读）。你粘进来的每一行，都会永久占据这个会话的视野。

`/compact`（有损压缩）尽量少用：阶段边界的正确动作是"写交接 → 新会话"，而不是把一锅粥压缩成一碗粥。

## 第二部分：三层上下文的手动落地（你要维护的全部东西）

一个研究项目目录里，你手动维护的核心只有 **5 个文件 + 3 个文件夹**（全部是普通 markdown/csv，手建一分钟，模板见附录 A）：

```
你的项目/
├── PROJECT_RULES.md     # L1 铁律：测试命令、数据路径、禁改项、指标定义。必须短，几乎不变
├── PROJECT_STATE.md     # L2 唯一真源：研究问题、当前阶段、唯一下一步、决策快照。1-2页
├── CLAUDE.md / AGENTS.md / GEMINI.md   # 各一句话，指向上面两个文件
├── RESEARCH_CONTRACT.md # 实验前冻结的承诺（第四部分第7步才写）
├── DECISION_LOG.md      # 只增不改的决策流水账（为什么采纳/否决，附证据）
├── cards/               # 资料卡、idea 卡（一事一卡）
├── handoffs/            # 交接包
└── runs/                # L3 噪声墓地：所有日志、原始输出（git 忽略）
```

**运转规则（你亲手执行的纪律，总共四条）：**

1. **任何会话开工第一句**：让它读 `PROJECT_RULES.md` + `PROJECT_STATE.md`，只做 STATE 里的「唯一下一步」。
2. **任何会话收工前**：让它更新 `PROJECT_STATE.md`（改阶段、写新的唯一下一步），把决策追加进 `DECISION_LOG.md`。**你亲眼核对这次更新**——这 30 秒是整个体系的质量闸门，也是"human in the loop"的落点。
3. **噪声永不进主会话**：安装、下载、训练、大范围检索 → 子代理或独立会话去干，产物写 `runs/`，只回传五行结论（干了什么/结果/证据路径/根因/下一步建议）。
4. **PROJECT_STATE 永远只有一个「唯一下一步」**。有两个就说明该拆分或该决策了。

为什么 STATE 要人来把关？因为它是所有会话的"启动内存"。它一旦被污染（写进了错误结论），污染会注入之后每一个新会话——等于系统性中毒。所以它必须短（你 30 秒能审完）、必须由你终审。

## 第三部分：角色 × 你的工具（怎么分工，为什么）

原文作者的分派（Gemini 搜索/发散、Codex 严审、Claude 拍板）是**他的领域里试出来的经验，不是定律**。ChatGPT 详解版的修正是对的：应该用小任务测你自己的方向。下表是**给你的起始配置**，用两周后按 3.2 的测法自行调整。

| 角色 | 干什么 | 用哪个工具（起始建议） | 为什么 |
|---|---|---|---|
| **Architect（拍板）** | 读各角色结论、做决定、推进阶段、维护 STATE | **你本人 + Claude Code 主会话** | 需要读写文件、有全局视野；且"最终必须有人拍板"——不搞模型互评无终局 |
| **Scout（检索）** | 建领域专家级上下文，产出资料卡 | **Claude Code 新会话**（用 grok-search + semantic-scholar MCP，能直接落盘卡片）；**Gemini CLI** 作第二路 | 你的 CC 挂了搜索和学术检索 MCP，检索完能直接写 cards/；Gemini 搜索广，交叉补漏 |
| **Generator（发散）** | 从干净起点提 10 个独立 idea | **Gemini CLI 或 web ChatGPT 新对话** | 要的就是"不知道历史"的白纸视野 + 发散性 |
| **Reviewer（评审）** | 一次一个 idea，GO/REVISE/KILL | **Codex 新会话**（每个 idea 单独开一个！） | 严格、不客套；隔离评审防"候选集偏差" |
| **Implementer（实现）** | 按冻结 contract 做最小改动 | **Codex**（纯代码 diff）或 **Claude Code**（涉及环境/工具链） | 小而准的 diff 是 Codex 强项 |
| **Runner（跑实验）** | 执行、监控、归档日志 | **Claude Code 子代理 / 独立会话**；远程一律 tmux | 脏活隔离；tmux 防断连（但防不了进程崩溃，仍要 checkpoint+日志+退出码） |
| **Analyst（判定）** | 按 contract 逐条 PASS/FAIL/INCONCLUSIVE | **Claude Code 新会话** 或 **web ChatGPT**（只粘 contract+结果表） | 视野里只有契约和数字，判定才不会被实现过程带偏 |

### 3.2 怎么测"哪个模型适合哪个角色"（半天完成）

给每个候选模型发同样的小任务，比结果：
- 搜 10 篇你方向的最近工作 → 数真实率、相关率、有没有漏掉你已知的关键论文；
- 给它一篇论文让它讲方法 → 看公式和假设讲没讲对；
- 给它一个你自己能判断好坏的 idea → 看它敢不敢杀（KILL），还是只会说"有潜力"；
- 让它修一个小 bug → 看是不是最小修改、有没有测试证据。

谁在哪项表现好，谁领哪个角色。**结论写进 DECISION_LOG，以后换模型版本了重测。**

## 第四部分：完整实战走查（案例：agent memory / 图结构记忆）

以下用一个具体研究问题贯穿全流程。每步给出：**开什么会话 → 粘什么（可直接复制）→ 它能看什么/不许看什么 → 产出什么 → 你检查什么**。

案例研究问题（示意，你可换）：
> 在多会话对话记忆评测（如 LoCoMo / LongMemEval 类基准）中，记忆写入时同步维护"实体-关系图"、检索时做 1 跳图扩展，相比纯向量检索，能否显著提升时序类与一致性类问题的准确率？

### 第 0 步：起项目（10 分钟，纯手动）

在空目录手建附录 A 的 5 个文件 + 3 个文件夹（或从任何地方抄模板——文件本身没有魔法）。`git init`，首次提交。在 `PROJECT_STATE.md` 写上研究问题草稿和唯一下一步："定义检索范围，开始文献侦察"。

### 第 1 步：把研究问题磨具体（Architect：你 + CC 主会话）

坏问题："研究怎么改进 agent 记忆"。好问题必须定死：任务、数据/基准、对照方法、主指标、约束。可以让我帮你磨：

```
读 PROJECT_RULES.md 和 PROJECT_STATE.md。帮我把研究问题磨到"可执行"：
逐项确定 任务/基准/对照/主指标/次指标/约束，每项给我2-3个选项和取舍理由，
最后把定稿写回 PROJECT_STATE.md 的研究问题栏。不要开始搜文献。
```

**你检查**：定稿是否你真想做的。这是全项目最重要的人类判断。

### 第 2 步：文献侦察（Scout：CC 新会话；Gemini CLI 走第二路）

**新开一个 CC 会话**（不是在主会话里搜！），粘：

```
先读 PROJECT_RULES.md 和 PROJECT_STATE.md。你本次角色：文献侦察员（Scout）。
只做检索和资料卡，不要提出任何 idea。

检索范围：
- 纳入：2023 年后；与多会话 agent 记忆的构建/检索/评测直接相关；有开源代码或正式发表优先
- 排除：纯 prompt 工程技巧；无任何评测的立场文章
- 已知起点（核实并向外扩展）：MemGPT、Mem0（及其图变体）、Zep/Graphiti、HippoRAG、
  A-Mem；基准：LoCoMo、LongMemEval

沿五个轴分别检索再组合：任务轴（多会话记忆）/方法轴（图记忆、KG检索）/
评测轴（时序推理、一致性）/系统轴（写入与检索延迟）/对照轴（纯向量RAG）。
用 grok-search 和 semantic-scholar 工具。能拿到 arXiv 源文/HTML 就不读 PDF；
初筛只读标题/摘要/引言/结论。

每篇入库论文在 cards/ 下建一张卡（模板见 cards/PAPER_CARD.md），
卡末尾严格分三段：直接事实 / 推断 / 未验证。
最后给我：入库清单一句话点评 + 「没搜到什么、哪里存疑」。
```

**你检查**：抽 2–3 张卡，点开原文核对"直接事实"段没有编造（AI 检索最大风险是幻觉引用）。**回主会话只带一句话**："侦察完成，N 张卡在 cards/，gap 是 XXX"，更新 STATE。

### 第 3 步：锚定并跑通对照（Runner：CC 子代理或独立会话）

agent-memory 领域的"复现 baseline" = 把评测基准 + 对照方法在你机器上跑通并拿到基线数字（比如：LoCoMo 官方评测脚本 + 纯向量检索记忆，QA 准确率 X%）。

在主会话对我说：

```
开一个子代理做这件事，不要把安装日志带回来：
克隆 <基准仓库>，装环境，用 <对照配置> 跑通最小评测（先 10 条样本冒烟，再全量），
所有输出存 runs/baseline-YYYYMMDD/，
只回报：命令 / 退出码 / 基线数字 / 证据文件路径 / 踩了什么坑。
```

**领域版复现阶梯**（原文的 9 级阶梯翻译到这里）：依赖能装 → 数据能加载 → 单条样本能过 → 10 条冒烟 → 全量单次 → 换 3 个随机种子重复（LLM 评测的"多 seed"= 改采样种子/温度/数据顺序重跑）→ 用官方评分脚本。
**铁律**：对照数字没拿到之前，不进入 idea 实验——否则以后分不清"是想法不行，还是评测本来就没跑对"。
**你检查**：基线数字与论文报告值在合理容差内（预先定容差，不追求逐位一致）。写入 `EVIDENCE_LEDGER.csv` 第一行 + `PROJECT_STATE.md` 权威对象栏。

### 第 4 步：发散 idea（Generator：Gemini CLI 或 web ChatGPT 新对话）

**新对话**，只粘三样东西：文献综合（你从卡片里挑关键 10 张的"方法一句话+gap"拼成一页）、对照能力边界（基线数字+已知短板）、约束（算力/API 预算/不许改评测脚本）。**绝不粘**：历史讨论、被否的想法、任何评审意见。

```
你是 idea 发散者。只基于我给的这一页文献综合、对照现状和约束工作。
一次给我 10 个互相独立的 idea，每个回答六问：
①改变了对照的什么 ②为什么可能有效 ③依赖什么假设 ④什么实验能推翻它
⑤最近的已有工作是什么 ⑥最小实现是什么。
禁止给自己排名。禁止写"加个XX可能提升表达能力"这种空话——
必须有现象、机制、可观测预测、可反证信号。
```

产出贴回 `cards/ideas/`，一个 idea 一个文件。

### 第 5 步：隔离评审（Reviewer：Codex，一个 idea 开一个新会话）

对**每个** idea 单独开一个 Codex 会话（10 个 idea = 10 个会话，这是刻意的）：

```
你是独立评审员。你的全部视野只有：下面的对照说明 + 这一个 idea。
不存在其他候选，不要做相对比较。

[对照] LoCoMo 评测，纯向量记忆，QA 总准确率 X%，时序子集 Y%，检索延迟 Z ms
[idea 卡] <粘一张卡的全文>

沿七个维度各打 1-5 分并给一句理由：新颖性/技术合理性/与对照的兼容性/
可证伪性/实现风险/成本风险/即使失败是否也能产生清晰知识。
另做 novelty 核查：列最近 3-5 篇最像的工作、共同点、真正差异、
哪些差异只是换了名字、有没有"已经被做过"的高风险。
最后必须三选一：GO / REVISE / KILL。REVISE 必须写清具体改什么。
```

结论追加到对应 idea 卡末尾。**为什么这么折腾**：把 10 个 idea 一起给评审者，它只会说"A 比 B 新颖"——相对比较会淹没绝对缺陷；隔离才能逼出"这个想法本身站不站得住"。

### 第 6 步：拍板（Architect：你 + CC 主会话）

回主会话：

```
读 cards/ideas/ 下所有带评审结论的卡。按判定和评分排序，
给我前 3 名的对比（各自最大风险是什么），你的推荐和理由。
我拍板后：把决定和理由写进 DECISION_LOG.md，把选中的 idea 编号写进 PROJECT_STATE.md，
被否决的在卡上标记 KILLED/HOLD 并注明原因。
```

**你做的事**：真的自己读前 3 张卡再拍板，不要只看我的推荐。拍板后，让选中的 idea 再过一次针对性检索（Scout 加急：专搜这个机制有没有人做过——novelty 审计）。

### 第 7 步：冻结 Research Contract（你 + 任一强模型起草，你终审）

**写代码之前**写 `RESEARCH_CONTRACT.md`。案例（可直接套改）：

```markdown
## 假设（可证伪）
在 LoCoMo 评测中，记忆写入时同步抽取实体-关系边、检索时做种子节点 1 跳图扩展，
通过把分散在多会话的同实体事实连通，提升时序类与一致性类问题的准确率。

## 成功信号（量化，事前定死）
- 3 个采样种子重复下，时序子集准确率均值 ≥ 对照 +3.0pt，且总体准确率不低于对照 -0.5pt
- 检索 P95 延迟增幅 ≤ 50%
- 3 次重复中至少 2 次时序子集为正提升

## 失败信号（独立列，不是"没成功"的反面）
- 提升主要来自回答变长/更啰嗦（用长度归一后消失）
- 总体持平但一致性子集显著下降（图引入了错误连接）
- 实体抽取错误率 > 20%（机制根基不成立）
- 换一个 embedding 模型后效应完全消失

## 停止规则
- pilot 最多 3 次；正式配置最多 2 个；API 预算上限 $N
- 若两次独立重复的时序子集都低于对照，停止，转入失败分析

## Ablation 预期
| 干预 | 机制成立应见 | 机制不成立应见 |
| 去掉图扩展只留抽取 | 收益大部分消失 | 不变 |
| 随机边替换真实边 | 显著劣于真实图 | 与真实图相当（说明收益是噪声） |
```

冻结后**不许改**；要改就写 `RESEARCH_CONTRACT_v2.md` 说明改了什么、为什么、改之前已经看到了哪些结果。**这是防"事后编故事"的唯一装置**——不事先写死，模型（和你自己）一定会在结果出来后合理化。

### 第 8 步：最小实现（Implementer：Codex 新会话）

```
先读 RESEARCH_CONTRACT.md 和 PROJECT_RULES.md。你是实现者。
只做最小改动实现 contract 里的干预：在 <记忆写入模块> 加实体-关系抽取，
在 <检索模块> 加 1 跳扩展开关（配置项 graph_expand: true/false）。
要求：
- graph_expand=false 时行为必须严格等于对照（这是不变量测试，写进测试）
- 不改评测脚本、不改数据处理、不动无关代码
- 新开 git 分支 idea/I00X
交付：改动文件清单 / diff 摘要 / 测试命令和输出 / commit 号 / 未决偏差。
不要解释实验意义——那不是你的工作。
```

**你检查**：跑一遍"关掉开关 = 对照"的测试。这一条保住了所有后续比较的公平性。

### 第 9 步：跑实验（Runner：CC 子代理；远程用 tmux）

冒烟（10 条）→ pilot（单种子，判断有没有基本信号，不许反复看测试集）→ 正式（3 种子全量，严格按 contract 配置）。每次 run 一个目录 `runs/<日期_commit_idea_种子>/`，存：命令、config 快照、commit 号、原始输出、评分结果、退出码。数字进 `EVIDENCE_LEDGER.csv`。
主会话只收五行结论。**日志一行都不进主会话。**

### 第 10 步：判定（Analyst：CC 新会话或 web ChatGPT）

**新会话**，只粘 contract + 结果表（就这两样，实现过程一个字不给）：

```
你是结果判定者。先完整读 contract，再看结果表。
逐条判定每个成功信号和失败信号：PASS / FAIL / INCONCLUSIVE，各附 run id。
严格区分四种话：描述性事实 / 不确定性 / 机制解释 / 替代解释。
禁止：移动成功标准、说"虽未达标但很有趣"、在证据不足时选边站。
重复间波动大、预算不一致、评分脚本变过、被单个异常 run 主导 → 判 INCONCLUSIVE。
```

判定回 STATE 和 DECISION_LOG。然后回到第 4/6 步循环（改进 or 换 idea or 写作）。
**记住原文那句话**：idea 本身不重要，探索中拿到的分析才真正属于你——失败但機制清楚的实验，价值高于莫名其妙的涨点。

## 第五部分：交接协议（什么时候换会话、交接包怎么写）

**触发条件**（满足任何一条就交接，别恋战）：
核心假设变了 / 代码分支变了 / 同一个 bug 三轮没收敛 / 会话里混了多个冲突想法 / AI 开始复读已被证伪的假设 / 日志占据大半对话 / 阶段切换（实现→分析、分析→写作）。

**交接包**（存 `handoffs/日期-主题.md`，新会话**只**读它+两个真源文件，绝不继承旧对话）：

```markdown
# 交接：<一句话主题>
目标：
权威文件：PROJECT_STATE.md / contract vN / commit <hash>
最小复现命令：
期望行为 vs 实际行为：
关键错误（证据文件路径，不贴全文）：
已试过什么：
哪些假设已被排除：
【还不知道什么】：←最重要的一段，让接手者补盲区而不是重走老路
唯一下一步：
```

在 Claude Code 里可以说"$handoff 下一步给XX做YY"让我代写（写完你过目）；在其他工具里就手动照模板写。**新会话的开场语**："读 PROJECT_RULES.md、PROJECT_STATE.md 和 handoffs/xxx.md，从『唯一下一步』继续。"

## 第六部分：我（Claude Code 里这个助手）的上下文系统，如何为你所用

坦白说明我的机制，你就知道怎么用我最省：
