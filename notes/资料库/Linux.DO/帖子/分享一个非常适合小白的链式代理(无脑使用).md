# 简单链式代理配置分享（两跳）

马上升3级了，搓个链式代理的yaml文件,给大家抛砖引玉.  

各位佬们，大家肯定有闲置机场吧，机场延迟那么低，家宽直链的延迟无法直视，有什么方法能用机场中转我的家宽呢？  

之前在论坛参考过草履虫大佬的链式代理对于刚开始的我可能还是有点不太熟悉,后来参考了隔壁站的大佬琢磨出了一套链式代理

## 原理解释：说白了就是套娃

其实 Mihomo 里的链式代理（配置文件里叫 `dialer-proxy`），意思就是"前置代理"。

举例子，你手头有一个香港机子线路好（做中转入口），还有一个台湾机子（做落地）。你想让流量先走香港，再从台湾出去。你只需要在台湾节点的配置里加上一句 `dialer-proxy: 香港节点`。

这就等于告诉台湾节点：“连你之前，先给我连香港！”

这时候流量的走向就变成了：

`你的设备 → 香港机 → 台湾机 → 互联网`

同样很多机场的延迟也很低，但是机场大部分都不提供转发功能，所以链式代理是能把吃灰机场利用一下的

我写了一个简单的两跳链式，是订阅链接式，手写节点的佬们还是自己去看官方文档吧，三跳的佬们看着改文件就是

优点就是把 入口 和 出口 都做成了 “组” 的形式。使用上更灵活可以随意搭配。

入口组我定义为 IN 组  

出口组我定义为 OUT 组

所有的分组里都写了OUT组

举例：IN 选 hk01，OUT 选 tw01， “Apple 组选 OUT”  

`Apple 组的流量最终路径：设备 → hk01 → tw01 → 互联网`

完整配置在 [https://raw.githubusercontent.com/uhovohu-glitch/clash/refs/heads/main/uhovohu-mihomo.yaml](https://raw.githubusercontent.com/uhovohu-glitch/clash/refs/heads/main/uhovohu-mihomo.yaml)

下边是代码片段

```
# Proxy 分组内包含 provider1 provider2 手动节点（无Link-OUT）

# 链式代理说明：
      # 本配置的链式代理 设计为 入口 IN组 和 出口 OUT组，分开管理，提供更大灵活性
      # 你的设备 → IN组（入口） → OUT组（出口） → 互联网
      
      #
      # IN 组：你的设备直接连接的节点，在此选择 入口
      #         来源：provider1 / provider2 / 手动节点
      #
      # OUT 组：最终连接互联网的节点，在此选择 出口
      #         来源：Link-OUT 订阅中的节点
      #
      
      # 其他策略组（Apple / Netflix 等）均内置 OUT 组选项
      
      # 例：IN 选 hk01，OUT 选 tw01，Apple 组选 OUT
      # Apple 组的流量最终路径：设备 → hk01 → tw01 → 互联网
      
      # 用法一 推荐把 所有节点(包含中转与落地) 并入一个订阅链接，在 provider1 与 Link-OUT 中引用相同链接使用
      # 用法二 把中转节点放入 provider1 订阅链接，落地节点放入 Link-OUT 订阅链接，分别在 IN 与 OUT 中引用

# =======================================================
# 1. 机场订阅 Proxy Providers
# =======================================================

proxy-providers:
  provider1:                                                                                    # 订阅链接，如需多个订阅请复制整段 并修改 provider1 字段 保证唯一性
    url: "填入订阅"
    type: http
    interval: 86400
    health-check: {enable: true,url: "https://www.gstatic.com/generate_204",interval: 300}
    proxy: DIRECT
  
  provider2:                                                                                    # 订阅链接，如需多个订阅请复制整段 并修改 provider2 字段 保证唯一性
    url: "填入订阅"
    type: http
    interval: 86400
    health-check: {enable: true,url: "https://www.gstatic.com/generate_204",interval: 300}
    proxy: DIRECT  
  
  Link-OUT:                                                                                     # 链路出口节点订阅，请尽量使用单独的订阅链接   或 "与上方订阅链接相同"  
    url: "填入订阅"
    type: http
    interval: 86400
    health-check: {enable: true,url: "https://www.gstatic.com/generate_204",interval: 300}
    proxy: DIRECT
    override:
      additional-prefix: "=> "                                                                  # 追加前缀 "=> " 以区分链路出口节点，方便在策略组中单独调用
      dialer-proxy: IN                                                                          # 关键：让这些节点在连接时自动经过 IN 组的当前选中节点

#proxies:                                                                                       # 手动节点的链式代理建议去参考官方文档填写
#  - name: "手动节点1"
#  - name: "手动节点2"
```

**一句话概括:使用链式代理IN组选入口节点 OUT组选出口(落地节点) Proxy选OUT 即为链式代理—如不使用链式代理Proxy组直接选自建节点亦或者机场的任意节点**
