## 摘要

近年来，基于大语言模型（LLM）的智能体受到了学术界与工业界的广泛关注。与原始 LLM 相比，基于 LLM 的智能体具有自我演化能力，这是解决需要智能体与环境长期、复杂交互的现实问题之基础。支持智能体-环境交互的关键组件是智能体的记忆。以往研究虽然提出了许多很有前景的记忆机制，但这些工作散见于不同论文，缺少从整体视角进行总结和比较的系统性综述，因而未能抽象出可启发后续研究的通用、有效设计模式。

为弥补这一空白，本文对基于 LLM 的智能体记忆机制展开全面综述。具体而言，首先讨论智能体记忆“是什么”以及“为什么需要”它；随后系统回顾如何设计和评估记忆模块；此外介绍多种记忆模块发挥重要作用的智能体应用；最后分析现有工作的局限，并指出重要的未来方向。为持续跟进该领域的最新进展，作者建立了仓库：<https://github.com/nuster1128/LLM_Agent_Memory_Survey>。

**图 1：记忆模块在基于 LLM 的智能体中的重要性。** 图中涵盖角色扮演、社会模拟、个人助理、开放世界游戏、代码生成、推荐、金融与医疗等应用；记忆为智能体提供技能与知识、环境上下文、个人偏好和历史经验。

## 1 引言

> “没有记忆，就没有文化；没有记忆，就不会有文明、社会和未来。”
>
> - Elie Wiesel（1928-2016）

近年来，大语言模型（LLM）在人工智能、软件工程、教育和社会科学等众多领域取得了显著成功 [1-3]。原始 LLM 通常不与环境交互便完成不同任务。然而，为实现通用人工智能（AGI）的最终目标，智能机器应能够通过自主探索现实世界并从中学习来改进自身。例如，旅行规划智能体若要预订机票，就应向票务网站发送订单请求，观察响应后再采取下一步行动；个人助理智能体则应根据用户反馈调整行为，提供个性化回答以提升用户满意度。为了进一步推动 LLM 向 AGI 迈进，近年涌现了大量关于基于 LLM 的智能体研究 [3, 4]，其关键在于为 LLM 配备额外模块，以增强它们在现实环境中的自我演化能力。

在所有新增模块中，记忆是区分智能体与原始 LLM、使智能体真正成为智能体的关键组件（见图 1）。它在智能体如何积累知识、处理历史经验以及检索有用知识来支持行动等方面起着极其重要的作用。围绕记忆模块，研究者投入了大量精力设计其信息来源、存储形式与操作机制。例如，Shinn 等人 [5] 同时纳入试次内和跨试次信息来构建记忆模块，以增强智能体的推理能力；Zhong 等人 [6] 以自然语言形式存储记忆信息，具备可解释性且对用户友好；Modarressi 等人 [7] 同时设计记忆读取和写入操作，使智能体能够通过与环境交互来解决任务。

尽管既有研究设计了许多很有前景的记忆模块，仍缺少从整体视角系统审视这些模块的工作。为弥补这一空白，本文全面回顾相关研究，提出清晰的分类体系以及设计、评估记忆模块的关键原则。具体讨论三个核心问题：

1. 基于 LLM 的智能体记忆是什么？
2. 为什么基于 LLM 的智能体需要记忆？
3. 如何实现并评估基于 LLM 的智能体记忆？

首先，本文详细阐释基于 LLM 的智能体记忆概念，分别给出狭义和广义定义。其次，从认知心理学、自我演化和智能体应用三个视角分析记忆的必要性。在回答“是什么”和“为什么”之后，介绍记忆模块设计与评估中的常用策略。对记忆设计，本文从记忆来源、记忆形式和记忆操作三个维度讨论既有工作；对记忆评估，介绍直接评估以及借助具体智能体任务进行间接评估两类常见方法。接着讨论角色扮演、社会模拟、个人助理、开放世界游戏、代码生成、推荐和专家系统等智能体应用，以展示记忆模块在实际场景中的重要性。最后分析现有工作的局限，并强调重要的未来方向。

本文的主要贡献可概括如下：

1. 正式定义记忆模块，并全面分析其对基于 LLM 的智能体的必要性。
2. 系统总结基于 LLM 的智能体记忆模块的设计与评估研究，给出清晰的分类体系和直观见解。
3. 介绍典型智能体应用，展示记忆模块在不同场景中的重要性。
4. 分析现有记忆模块的关键局限并给出潜在解决思路，以启发后续研究。

## 2 相关综述

过去两年，LLM 受到学术界和工业界的广泛关注。为系统总结该领域的研究，研究者撰写了大量综述。本节简要回顾这些综述（整体概览见图 2），重点说明其主要关注点和贡献，从而更准确地定位本文。

### 2.1 大语言模型综述

在 LLM 领域，Zhao 等人 [70] 给出了第一篇综合性综述，总结 LLM 的背景、演化路径、模型架构、训练方法和评估策略。Hadi 等人 [71] 和 Min 等人 [72] 也从整体视角开展 LLM 综述，但采用了不同的分类体系和理解框架。在这些综述之后，研究者进一步深入 LLM 的特定方面，回顾相应的里程碑工作与关键技术。这些方面可分为四类：基础问题、评估、应用和挑战。

**基础问题。** 此类综述旨在总结可用于处理 LLM 基础问题的技术。具体而言，Zhang 等人 [8] 全面综述监督微调方法，这是更好地训练 LLM 的关键技术；Shen 等人 [9]、Wang 等人 [10] 和 Liu 等人 [11] 综述 LLM 对齐，这是使 LLM 输出符合人类价值观的关键要求；Gao 等人 [12] 综述 LLM 的检索增强生成（RAG）能力，这对于向 LLM 提供事实性、时效性知识并减少幻觉至关重要；Qin 等人 [18] 总结使 LLM 能够使用外部工具的先进方法，这是扩展 LLM 在需要专业知识的领域中之能力的基础。

Wang 等人 [13]、Yao 等人 [14]、Wang 等人 [15]、Feng 等人 [16] 和 Zhang 等人 [17] 综述 LLM 知识编辑，这对于定制 LLM 以满足特定需求十分重要。Huang 等人 [19]、Wang 等人 [20] 和 Pawar 等人 [21] 关注 LLM 的长上下文能力，这对于让 LLM 每次处理更多信息并拓展应用场景至关重要。Wu 等人 [22]、Song 等人 [23]、Caffagni 等人 [24] 和 Yin 等人 [25] 总结多模态 LLM，将其能力从文本扩展到视觉及其他模态。

上述综述主要关注 LLM 的有效性，另一重要方面则是训练和推理效率。为总结这一方向，Zhu 等人 [30]、Xu 和 McAuley [31]、Wang 等人 [32] 以及 Park 等人 [33] 系统回顾模型压缩技术。Ding 等人 [81] 和 Xu 等人 [29] 分析并总结参数高效微调研究。Bai 等人 [26]、Wan 等人 [27]、Miao 等人 [28] 和 Ding 等人 [81] 则更广泛地关注资源利用效率。

**评估。** 此类综述关注如何评估 LLM 能力。Chang 等人 [34] 从整体视角全面总结评估方法，涵盖用于评估 LLM 性能的不同任务、方法和基准。Guo 等人 [35] 更关注评估目标，说明如何评估 LLM 的知识、对齐与安全控制能力，从而补充性能之外的评估指标。

**应用。** 此类综述总结利用 LLM 改进各类应用的模型。具体而言，Zhu 等人 [37] 聚焦信息检索（IR），总结基于 LLM 的查询处理研究；Xu 等人 [38] 更关注信息抽取（IE），为该领域的 LLM 方法提供全面分类；Li 等人 [50]、Lin 等人 [51] 和 Wang 等人 [52] 讨论 LLM 在推荐系统中的应用，其中利用智能体生成数据并提供推荐；Fan 等人 [39]、Wang 等人 [40] 和 Zheng 等人 [41] 关注 LLM 如何从软件设计、开发和测试等方面促进软件工程（SE）；Zeng 等人 [42] 总结机器人领域的 LLM 方法；Cui 等人 [43] 和 Yang 等人 [44] 聚焦自动驾驶，从不同视角总结该领域的 LLM 模型。

除上述人工智能领域外，LLM 也被用于自然科学和社会科学。He 等人 [45]、Zhou 等人 [46] 和 Wang 等人 [47] 总结 LLM 在医学中的应用；Li 等人 [48] 关注 LLM 在金融中的应用；He 等人 [49] 回顾利用 LLM 推动心理学发展的模型。

**挑战。** 此类综述关注 LLM 的可信性问题，包括幻觉、偏差、不公平、可解释性、安全和隐私。LLM 幻觉是指模型可能生成错误认知或虚构内容，从而影响其在下游应用中的可靠性。Zhang 等人 [53]、Huang 等人 [54]、Rawte 等人 [55]、Ye 等人 [56]、Ji 等人 [57]、Tonmoy 等人 [58] 和 Jiang 等人 [59] 总结了缓解 LLM 幻觉问题的主流模型。

偏差与不公平问题指 LLM 可能不平等地对待不同人群或对象，进而传播社会刻板印象和歧视。Gallegos 等人 [60]、Kotek 等人 [61] 和 Li 等人 [62] 全面讨论这些挑战并总结缓解方法。可解释性问题指 LLM 的内部工作机制仍不清楚；Zhao 等人 [63] 系统讨论这一问题并总结提升可解释性的既有努力。安全和隐私同样具有挑战性，Yao 等人 [64]、Shayegani 等人 [65]、Neel 和 Chang [66]、Smith 等人 [67]、Dong 等人 [68] 以及 Das 等人 [69] 已对此开展全面综述。

**图 2：LLM 与基于 LLM 的智能体相关综述的组织结构。** LLM 综述覆盖基础问题（监督微调、对齐、检索增强、知识编辑、工具使用、长上下文、多模态、效率）、评估、应用（信息处理、软件工程、机器人、自动驾驶、医学、金融、心理学、推荐）与挑战（幻觉、偏差与公平、可解释性、安全）。基于 LLM 的智能体综述覆盖基础问题（规划、记忆、多智能体）、评估、应用与挑战；本文定位于其中的“记忆”。

### 2.2 基于大语言模型的智能体综述

借助 LLM 的能力，研究者开展了大量构建基于 LLM 的智能体的研究。这些智能体可以自主感知环境、采取行动、积累知识并实现自我演化。Wang 等人 [3] 给出了第一篇系统性综述，从智能体构建、智能体应用和智能体评估三个视角总结基于 LLM 的智能体。Xi 等人 [4]、Zhao 等人 [77]、Cheng 等人 [78] 和 Ge 等人 [80] 也从整体视角总结相关研究，但各自关注点和分类体系不同，因而带来了对该领域更为多样的理解。

除整体综述外，还出现了若干回顾基于 LLM 的智能体特定方面的论文。在基础问题方面，Durante 等人 [79] 总结多模态智能体研究，Huang 等人 [74] 关注基于 LLM 的智能体规划能力，Guo 等人 [75] 更关注多智能体交互场景。在应用方面，Li 等人 [76] 总结被用作个人助理的基于 LLM 的智能体。

**本文定位。** 本综述总结基于 LLM 的智能体的一项基础问题，即智能体记忆机制。据作者所知，这是该方向的第一篇综述。作者希望它既能启发未来更先进的记忆架构，也能为初学者提供全面的入门材料。

## 3 基于 LLM 的智能体记忆是什么

与环境交互并从中学习，是基于 LLM 的智能体的一项基本要求。在智能体-环境交互过程中有三个关键阶段：

1. 智能体从环境中感知信息，并将其存入记忆；
2. 智能体处理已存储的信息，使其更易于使用；
3. 智能体根据处理后的记忆信息采取下一步行动。

记忆在所有这些阶段都极为重要。下面先从狭义和广义两个角度定义智能体记忆，再详细说明上述三个阶段如何借助记忆模块执行。

### 3.1 基础知识

为便于清晰表述，先介绍几个重要的背景概念。

**定义 1（任务）。** 任务是智能体需要实现的最终目标，例如为 Alice 预订机票、为 Bob 推荐餐厅等。形式化地，以下用 $T$ 表示任务，并用下标标记不同任务。

**定义 2（环境）。** 狭义而言，环境是智能体为完成任务而需要与之交互的对象。对定义 1 中的示例，环境分别是 Alice 和 Bob，他们会对智能体的行动提供反馈。广义而言，环境可以是影响智能体决策的任何上下文因素，例如预订机票时的天气、推荐餐厅时的时间和地点等。

**定义 3（试次与步骤）。** 为完成任务，智能体需要与环境交互。通常，智能体先采取一个行动，环境再对该行动作出响应；随后，智能体根据响应采取下一行动。这个过程不断迭代，直至任务完成。完整的智能体-环境交互过程称为一个“试次”（trial），每轮交互称为一个“步骤”（step）。在每个试次中，智能体可采取多个步骤形成任务的一个潜在解；对每项任务，智能体可以探索多个试次以完成任务 [5]。形式化地，在步骤 $t$，用 $a_t$ 和 $o_t$ 分别表示智能体行动和观察到的环境响应。一个长度为 $T$ 的试次可表示为：

$$
\xi_T=\{a_1,o_1,a_2,o_2,\ldots,o_T,a_T\}.
$$

在上述定义中，任务和环境是粒度最粗的概念，步骤则是粒度最细的概念。三者共同描述完整的智能体-环境交互过程。

**示例。** 基于上述定义，下面给出一个贯穿全文的示例，以提供更直观的理解。智能体有两个任务：

- **任务 A：** 为 Alice 制订 2024 年 5 月 1 日至 5 月 3 日的北京旅行计划。智能体需要：（1）购买往返机票；（2）根据 Alice 的偏好确定若干景点；（3）安排这些景点的游览顺序。
- **任务 B：** 为 Alice 推荐一部 2024 年 5 月 10 日观看的电影。智能体需要：（1）确定 Alice 有空看电影的时间；（2）根据她的观影偏好选择电影。

每项任务的一个潜在试次如下（也见图 3(a)）。

**任务 A：**

> **[步骤 1] 智能体：** 我需要通过在线票务中心预订 2024 年 5 月 1 日从上海到北京、以及 2024 年 5 月 3 日从北京到上海的机票。<br>
> **环境（在线票务中心）：** 订单已确认。去程航班上午 9:00 起飞，票号为 EK240501SX9021；返程航班下午 4:30 起飞，票号为 LG240503FN6317。请准时到达机场乘机。
>
> **[步骤 2] 智能体：** 我从《北京景点》杂志获得了外部知识，得知长城、故宫和颐和园都很有名。根据 Alice 的偏好，我认为她喜欢古代建筑，因此将故宫和颐和园确定为目的地。<br>
> **环境（Alice）：** 做得好！
>
> **[步骤 3] 智能体：** 现在需要为 Alice 安排游览顺序。根据上述信息，我建议她抵达北京后游览颐和园，因为那里适合花一整个下午游览并观赏日落。第二天再去故宫，这样时间会很充裕。最后，她可以在第三天返回上海并休息。<br>
> **环境（Alice）：** 我很喜欢这个计划，谢谢！

**任务 B：**

> **[步骤 1] 智能体：** 根据过去为 Alice 推荐电影的经验，她喜欢晚上 9:00 开始看电影，因为那时已经下班。我应该询问 Alice 那个时间是否方便。<br>
> **环境（Alice）：** 当然，那个时间很好！
>
> **[步骤 2] 智能体：** 现在需要在 Netflix 中找出 Alice 标记为“想看”的电影。<br>
> **环境（Netflix）：** Alice 的想看列表：《星际穿越》《恐怖星球》和《鬼吹灯》。
>
> **[步骤 3] 智能体：** 由于 Alice 从不在晚上看恐怖片，《星际穿越》会更适合她。现在需要向 Alice 确认这部电影。<br>
> **环境（Alice）：** 太好了！我喜欢它！

### 3.2 智能体记忆的狭义定义

狭义而言，智能体记忆仅与同一试次内的历史信息有关。形式化地，对给定任务，步骤 $t$ 之前的试次历史为：

$$
\xi_t=\{a_1,o_1,a_2,o_2,\ldots,a_{t-1},o_{t-1}\},
$$

记忆由 $\xi_t$ 推导得到。在上述示例的任务 A 中，智能体需要在步骤 3 为 Alice 安排游览顺序，此时其记忆包含步骤 1 和步骤 2 中选定景点及抵达时间的信息。在任务 B 中，智能体需要在步骤 3 为 Alice 选择电影，此时其记忆包含已安排的观影时间。

### 3.3 智能体记忆的广义定义

广义而言，智能体记忆可来自范围更广的信息源，例如跨不同试次的信息，以及超出智能体-环境交互之外的外部知识。形式化地，给定一系列连续任务 $\{T_1,T_2,\ldots,T_K\}$，对任务 $T_k$，步骤 $t$ 的记忆信息来自三类来源：

1. **同一试次内的历史信息：** $\xi_t^k=\{a_1^k,o_1^k,\ldots,a_{t-1}^k,o_{t-1}^k\}$，其中上标 $k$ 标记任务索引。
2. **跨不同试次的历史信息：** $\Xi^k=\{\xi^1,\xi^2,\ldots,\xi^{k-1},\xi'^k\}$，其中 $\xi^j$（$j\in\{1,\ldots,k-1\}$）表示任务 $j$ 的试次，$\xi'^k$ 表示此前为任务 $T_k$ 探索过的试次。每项任务可有多个试次来探索最终解，且都可纳入记忆。
3. **外部知识：** 记为 $D_t^k$。

智能体记忆由 $(\xi_t^k,\Xi^k,D_t^k)$ 推导得到。在任务 A 中，如果存在若干失败试次，即 Alice 给出负面反馈，那么这些试次可纳入智能体记忆，以避免未来出现类似错误，对应 $\xi'^k$。在任务 B 中，智能体可以推荐与 Alice 在任务 A 中参观过的景点相关的电影，以捕捉她近期的偏好，对应 $\{\xi^1,\xi^2,\ldots,\xi^{k-1}\}$。在决策过程中，智能体还参考了《北京景点》杂志来制订旅行计划，这是当前任务 $T_k$ 的外部知识，对应 $D_t^k$。

### 3.4 记忆辅助的智能体-环境交互

如第 3 节开头所述，智能体-环境交互包含三个关键阶段。智能体记忆模块通过三种操作实现这些阶段：记忆写入、记忆管理和记忆读取。

**记忆写入。** 该操作旨在将原始观察映射为实际存储的、信息量更高 [7] 且更简洁 [6] 的记忆内容，对应智能体-环境交互的第一阶段。给定任务 $T_k$，若智能体在步骤 $t$ 采取行动 $a_t^k$，环境提供观察 $o_t^k$，则记忆写入操作可形式化为：

$$
m_t^k=W(\{a_t^k,o_t^k\}),
$$

其中 $W$ 是映射函数，$m_t^k$ 是最终存储的记忆内容，可以是自然语言，也可以是参数化表示。在示例的任务 A 中，步骤 2 结束后智能体应记住航班安排和景点选择；在任务 B 中，步骤 1 结束后应记住 Alice 希望晚上 9:00 看电影这一事实。

**记忆管理。** 该操作旨在处理已存储的记忆信息，使其更有效，例如总结高层概念以提高智能体的泛化能力 [6]、合并相似信息以减少冗余 [7]，以及遗忘不重要或不相关的信息以消除其负面影响。该操作对应智能体-环境交互的第二阶段。设 $M_{t-1}^k$ 为任务 $k$ 在步骤 $t$ 之前的记忆内容，$m_t^k$ 为通过记忆写入操作在步骤 $t$ 存储的信息，则记忆管理操作为：

$$
M_t^k=P(M_{t-1}^k,m_t^k),
$$

其中 $P$ 是迭代处理已存储记忆信息的函数。按狭义记忆定义，迭代只发生在同一试次内，试次结束时清空记忆；按广义定义，迭代可跨不同试次甚至不同任务，也包括外部知识的整合。在任务 B 中，智能体可总结出 Alice 喜欢在晚上观看科幻电影，并将其作为未来向 Alice 推荐电影的默认规则。

**记忆读取。** 该操作旨在从记忆中获得重要信息，以支持智能体的下一步行动，对应智能体-环境交互的第三阶段。设 $M_t^k$ 为任务 $k$ 在步骤 $t$ 的记忆内容，$c_t^k$ 为下一行动的上下文，则记忆读取操作为：

$$
\hat{M}_t^k=R(M_t^k,c_{t+1}^k),
$$

其中 $R$ 通常通过计算 $M_t^k$ 与 $c_{t+1}^k$ 的相似度实现 [82]。$\hat{M}_t^k$ 会成为最终提示的一部分，用于驱动智能体的下一行动。在任务 B 中，智能体于步骤 3 决定最终推荐的电影时，应聚焦步骤 2 的“想看”列表并从中选择。

根据上述操作，可以推导出从 $\{a_t^k,o_t^k\}$ 演化到 $a_{t+1}^k$ 的统一函数：

$$
a_{t+1}^k=\operatorname{LLM}\left\{R\left(P\left(M_{t-1}^k,W(\{a_t^k,o_t^k\})\right),c_{t+1}^k\right)\right\}.
$$

其中 $\operatorname{LLM}$ 表示大语言模型。对该函数反复展开，即可得到完整的智能体-环境交互过程，直观示意见图 3(b)。

**说明。** 这一函数给出了智能体记忆过程的一般形式。既有工作可能采用不同的具体设定。例如，在 [5] 中，$R$ 与 $P$ 被设为相同函数，且 $P$ 只在一个试次结束时生效；在 Park 等人 [83] 中，$R$ 基于相似度、时间间隔和重要性三项标准实现，$P$ 则通过反思过程生成更抽象的思考。本节关注智能体记忆操作的总体框架；$W$、$P$ 和 $R$ 的具体实现将在第 5 节详细介绍。

## 4 为什么基于 LLM 的智能体需要记忆

上文介绍了基于 LLM 的智能体记忆是什么。在全面说明如何实现记忆之前，本节从认知心理学、自我演化和智能体应用三个视角，简要说明为什么记忆是构建基于 LLM 的智能体所必需的。

### 4.1 认知心理学视角

认知心理学是对注意、语言使用、记忆、知觉、问题求解、创造力和推理等人类心理过程的科学研究。在这些过程中，记忆被普遍视为极为重要的一项 [84]。它是人类通过积累重要信息、抽象高层概念来学习知识 [85]，通过记住文化价值和个人经验来形成社会规范 [86]，以及通过设想潜在的正面与负面后果来采取合理行为 [87] 的基础。

基于 LLM 的智能体的一项主要目标，是替代人类完成不同任务。要让智能体像人一样行动，依照人类的工作机制设计智能体是一种自
然且必要的选择 [88]。既然记忆对人类十分重要，设计记忆模块对智能体也同样重要。此外，认知心理学已有悠久的研究历史，积累了许多有效的人类记忆理论和架构，可用于支持智能体获得更先进的能力 [89]。

### 4.2 自我演化视角

为完成不同的实际任务，智能体必须在动态环境中实现自我演化 [90]。在智能体-环境交互过程中，记忆对以下方面至关重要：

1. **经验积累。** 记忆的一项重要功能是保存过去错误的规划、不恰当的行为或失败经验，从而使智能体未来能够更有效地处理类似任务 [91]。这对提高智能体在自我演化过程中的学习效率极其重要。
2. **环境探索。** 为在环境中自主演化，智能体必须探索不同的行动并从反馈中学习 [92]。通过保存历史信息，记忆可帮助智能体更好地决定何时以及如何进行探索，例如更多关注此前失败的试次，或探索频率较低的行动 [93]。
3. **知识抽象。** 记忆的另一重要功能，是从原始观察中总结、抽象高层信息，这是使智能体适应未见环境并提高泛化能力的基础 [82]。

总之，自我演化是基于 LLM 的智能体的基本特征，记忆则是自我演化的关键。

### 4.3 智能体应用视角

在许多应用中，记忆是智能体不可或缺的组成部分。例如，对话智能体的记忆存储历史对话信息，这是生成下一条回复所必需的；没有记忆，智能体便不知道上下文，也无法继续对话 [94]。对模拟智能体而言，记忆对于使智能体持续遵循角色设定十分重要；没有记忆，智能体可能在模拟过程中轻易脱离角色 [95]。这两个示例都说明，记忆并非可选组件，而是智能体完成给定任务的必需组件。

在上述三个视角中，第一个揭示记忆构成了智能体的认知基础；第二和第三个说明记忆对于智能体的演化原则与应用不可或缺，为设计具有记忆机制的智能体提供了启示。

#### 5.1.1 试次内信息

在智能体-环境交互过程中，同一试次内的历史步骤通常是支持智能体后续行动的最相关、信息量最大的信号。几乎所有既有工作都将其用作记忆来源的一部分。

**代表性研究。** Generative Agents [83] 旨在利用基于 LLM 的智能体模拟人类日常行为。智能体记忆源于为实现目标而采取的历史行为，例如研究某一主题时收集相关论文。MemoChat [94] 旨在与人类聊天，其智能体记忆由一个对话会话的历史构成。TiM [97] 在完成任务后自行生成多条思路，并将其用作记忆来提供泛化能力更强的信息，以增强智能体的推理能力。Voyager [99] 聚焦于构建 Minecraft 游戏智能体，其记忆包含完成任务所需的初步、基础行动的可执行代码。应注意，试次内信息不仅包括智能体-环境交互，还包括时间、地点等交互上下文。

**讨论。** 试次内信息与智能体当前需要完成的任务高度相关，因此是构建记忆时最显然、最直观的信息源。但仅依赖试次内信息，可能使智能体无法从不同任务中积累有价值的知识，也难以学习泛化能力更强的信息。因此，许多研究还探索如何有效利用跨不同任务的信息来构建记忆模块。

#### 5.1.2 跨试次信息

对基于 LLM 的智能体而言，在环境中跨多个试次积累的信息也是记忆的重要组成部分，通常包括成功和失败的行动及其启示，例如失败原因、取得成功的通用行动模式等。

**代表性研究。** 最具代表性的研究之一是 Reflexion [5]，它为基于 LLM 的智能体提出语言强化学习。该方法以语言形式从过去试次中提炼经验，并将其用于后续试次，以提高同一任务上的表现。Retroformer [103] 进一步微调反思模型，使智能体能更有效地从过去试次中提取跨试次信息。Synapse [91] 中的智能体专注于解决计算机控制任务，其记忆可以通过成功示例记录跨试次信息，并在相似试次中用作参考。ExpeL [82] 要求智能体在环境中解决一系列复杂的交互式任务；它存储并组织已完成的轨迹，为新任务召回相似轨迹，并将召回轨迹中的成功案例与失败案例比较，以识别成功模式。

**讨论。** 借助跨试次信息积累的记忆，智能体能够积累经验，这对其演化很重要。基于过去经验，智能体可以根据整个过程的总体反馈调整行动。试次内观察可视为短期记忆，而试次经验则可视为长期记忆；后者利用不同试次的反馈支持更广泛的智能体试次，为智能体提供更持久的经验支持。但其局限在于，试次内和跨试次信息都要求智能体亲自参与智能体-环境交互，因而没有包含外部经验和知识。

#### 5.1.3 外部知识

基于 LLM 的智能体的一项重要特征，是人们可以直接用自然语言与其交流和控制它。因此，智能体能够方便地纳入文本形式的外部知识，例如 Wikipedia，以辅助决策。

**代表性研究。** 在 ReAct [104] 中，智能体需要通过多步推理回答常识问题；如果推理过程中缺少信息，可以使用 Wikipedia API 获取外部知识。GITM [93] 旨在设计可在复杂、稀疏奖励的 Minecraft 环境中探索的智能体；智能体从在线 Minecraft Wiki 和合成配方中获取知识，为导航提供无限的知识来源。CodeAgent [114] 聚焦仓库级代码生成任务，这类任务通常涉及复杂依赖和大量文档，因此设计了网络搜索策略来获取相关外部知识。ChatDoctor [115] 将基于 LLM 的智能体适配到医学领域，并微调一个知识获取过程，从 Wikipedia 和医学数据库中检索外部知识。

**讨论。** 外部知识可来自私有或公共来源，为基于 LLM 的智能体提供其内部环境之外的大量知识，其中一些知识很难甚至不可能通过智能体-环境交互获得。此外，大多数外部知识都可根据任务需要，通过各类工具的 API 实时、动态获取，从而缓解知识过时问题。把外部知识整合进记忆，显著扩展了基于 LLM 的智能体的知识边界，为决策提供近乎无限、时效性强且有依据的知识。

#### 5.2.1 文本形式的记忆

文本形式目前是表示记忆内容的主流方法，其特点是可解释性较好、实现较容易、读写效率较高。文本形式既可以是原始自然语言等非结构化表示，也可以是元组、数据库等结构化信息。总体而言，既有研究用文本形式的记忆存储四类信息：（1）完整的智能体-环境交互；（2）近期的智能体-环境交互；（3）检索得到的智能体-环境交互；（4）外部知识。前三类用自然语言描述智能体-环境交互循环内的信息，最后一类则用自然语言存储循环之外的信息。

**完整交互。** 此方法借助长上下文策略 [116] 存储智能体-环境交互历史中的全部信息。在第 3.1 节的任务 A 中，步骤 2 结束后的智能体记忆可通过拼接步骤 2 之前的所有信息来实现，最终的文本形式记忆是：“你的记忆是：[步骤 1]（智能体）……（在线票务中心）……[步骤 2]……请根据你的记忆进行推断。”

既有工作采用不同策略存储记忆信息。例如，LongChat [116] 中的智能体专注于理解长上下文场景中的自然语言，并微调基础模型，使其更适于记住完整交互。Memory Sandbox [117] 旨在缓解无关记忆对对话的影响，设计透明、交互式的智能体记忆管理方法，先移除无关记忆，再将其拼接为提示。此外，一些工作致力于增强 LLM 处理更长上下文的能力 [118, 119]。

虽然存储全部智能体-环境交互可以保留完整信息，但它在计算成本、推理时间和推理稳健性方面有明显局限。第一，实际应用中快速增长的长上下文记忆会显著提高 LLM 推理成本，因为注意力计算的时间复杂度会随序列长度呈二次增长。这需要更多计算资源并显著增加推理延迟，阻碍实际部署。第二，随着记忆快速增长，其长度很容易超过 LLM 预训练时的序列长度上限，因而必须截断，造成智能体记忆不完整和信息丢失。第三，它可能引入偏差并降低推理稳健性。既有研究 [120] 表明，文本片段在长上下文中的位置会显著影响其被利用的程度，因此长上下文提示中的记忆无法得到平等、稳定的处理。这些缺点说明，基于 LLM 的智能体需要额外设计记忆模块，而不能只是简单地把所有信息拼接进提示。

**近期交互。** 此方法用自然语言存储和维护最近获得的记忆，并根据局部性原理 [121] 提高记忆信息的利用效率。在第 3.1 节的任务 B 中，可以只记住 Alice 近三年的偏好并截断更久远的部分，其中“近三年”可视为记忆窗口大小。

既有研究采用多种策略存储近期文本记忆。例如，SCM [98] 提出一种基于缓存机制的闪存，保留最近 $t-1$ 个时间步的观察，旨在增强信息的时近性。MemGPT [100] 将智能体视为操作系统，使其能通过自然接口与用户动态交互，并设计“工作上下文”来保存近期历史，作为虚拟上下文管理的一部分。RecAgent [95] 设计智能体模拟电影推荐中的用户行为，将部分时间性信息存入短期记忆，作为中间缓存，以模拟人脑的记忆机制 [122, 123]。这些代表性方法可根据近期交互动态更新记忆，并更加关注对当前阶段重要的近期上下文。

按时近性缓存记忆，是提升记忆效率并让智能体更关注近期信息的有效方法。然而，在长期任务中，此方法无法访问遥远记忆中的关键信息，可能丢失不在当前缓存窗口内却十分重要的内容。换言之，强调时近性会天然忽略较早但关键的信息，因此会给需要全面理解过去事件的场景带来挑战。

**检索交互。** 与按时间截断记忆的方法不同，此方法通常根据相关性、重要性和主题选择记忆内容。它确保决策过程能够纳入遥远但关键的记忆，从而弥补只记忆近期信息的局限。在任务 A 中，Alice 的偏好在任务开始前已存入记忆。到步骤 2 时，智能体根据查询关键词“旅行”从记忆中检索 Alice 偏好中最相关的方面，得到她喜欢古代建筑景点这一信息。

一般而言，检索方法在写入记忆时会生成嵌入作为记忆条目的索引，并记录辅助信息以支持检索；读取记忆时为每个记忆条目计算匹配分数，把排名前 $K$ 的条目用于智能体决策。

既有研究中，大多数智能体都使用检索方法处理记忆信息。例如，Park 等人 [83] 先通过余弦相似度计算当前上下文与记忆条目的相关性，再根据辅助信息获得重要性和时近性。MemoryBank [6] 使用双塔稠密检索模型，从过往对话中寻找相关信息；每个记忆条目被编码为嵌入，并由 FAISS [124] 建立索引以提高检索效率；读取记忆时，将当前上下文编码为表示，以获得最相关的记忆。RET-LLM [7] 旨在设计可通用的记忆读写模块，利用局部敏感哈希（LSH）在数据库中检索包含相关条目的元组，从而提供更多信息。ChatDB [96] 则使用符号记忆，通过生成 SQL 语句在数据库中检索存储的信息。

检索方法高度依赖于能否准确、高效地获得预期信息。不准确的检索策略可能获取与智能体推理无关、无益的信息；笨重的检索系统则可能造成高计算成本和长时间延迟，尤其是在处理海量信息时。此外，检索方法通常存储环境内部的同质信息，即所有信息形式一致。对环境之外的异质信息，很难直接采用同一方法存储记忆。

**外部知识。** 为获取更多信息，一些智能体会调用工具获取外部知识，把额外的相关知识转化为自己的记忆用于决策。通过应用程序接口（API）访问外部知识是一种常见做法 [5, 104]。如今，Wikipedia 和 OpenWeatherMap 等丰富的公共信息可在线获得，并能通过 API 便捷访问。在任务 A 的步骤 2 中，智能体就是通过工具从数字杂志中取得外部知识。

在既有模型中，Toolformer [125] 提出教会 LLM 使用工具，使其可以获取外部知识来更好地解决任务。ToolLLM [126] 使 Llama [127] 能够使用 RapidAPI 中更多的 API，并支持多工具使用，从而提供扩展智能体能力的通用接口。TPTU [110] 将任务规划和工具使用同时纳入智能体，以处理复杂问题；后续工作 [111] 进一步广泛增强其检索等能力。ToRA [128] 要求智能体解决数学问题，并利用模仿学习增强使用程序化工具的能力。

上述方法允许智能体从多样来源获取时效性强的现实世界信息，显著提升了智能体能力。但这些信息可能包含错误和偏差，可靠性存疑 [18]。此外，把工具集成进智能体，要求智能体具备全面的理解能力，才能在不同上下文中解释检索结果；这可能提高计算成本，也会增加外部数据与内部决策过程对齐的复杂性。使用外部 API 还带来隐私、数据安全和使用政策合规方面的顾虑，需要严格管理和监督 [18]。

#### 5.2.2 参数形式的记忆

另一类方法以参数形式表示记忆。参数记忆不会额外占用提示中的上下文长度，因此不受 LLM 上下文长度限制。不过，参数形式的记忆目前研究仍不充分，既有工作可分为两类：微调方法和记忆编辑方法。

**微调方法。** 把外部知识整合进智能体记忆，可以在通用知识之上丰富领域专门知识。监督微调是将领域知识注入 LLM 的常用方法，它让智能体拥有领域专家的记忆，并显著增强智能体完成特定领域任务的能力。在任务 A 中，可在任务开始前将杂志中的景点外部知识微调进 LLM 参数。

既有工作中，Character-LLM [105] 关注角色扮演场景，使用角色相关数据（如经历）进行监督微调，使智能体具备特定角色的特质和特征。Huatuo [107] 旨在赋予智能体生物医学领域的专业能力，尝试在中文医学知识库上微调 Llama [127]。为了创建人工医生，DoctorGLM [129] 用 LoRA [131] 微调 ChatGLM [130]；Radiology-GPT [132] 则通过在带标注的放射学数据集上进行监督微调，增强放射学分析领域知识。InvestLM [113] 收集投资数据并进行微调，以提升金融投资领域的专门能力。


微调方法能有效缩小通用智能体与专业智能体之间的差距，提高智能体在要求领域信息高度准确、可靠的任务中的能力。但为特定领域微调 LLM 可能导致过拟合，也会引发灾难性遗忘，即 LLM 因参数更新而忘记原有知识。微调的另一局限是计算和时间成本高，且需要大量数据。因此，大多数微调方法适用于离线场景，很少能处理在线场景，例如用智能体观察和试次经验进行微调。由于智能体-环境交互频繁，在在线动态交互的每一步都用反向传播进行微调，成本无法承受。

**记忆编辑方法。** 除微调外，将记忆注入模型参数的另一类方法是知识编辑 [133, 134]。微调方法从特定数据集中提取模式，而知识编辑则只针对需要改变的事实进行调整，确保无关知识不受影响。知识编辑更适合小规模记忆调整，通常计算成本较低，更适合在线场景。在任务 B 中，智能体记忆显示 Alice 总在晚上 9:00 看电影；但她近期可能换了工作，晚上 9:00 不再有空。此时应编辑相关记忆，例如晚上 9:00 的日程惯例，这可以用知识编辑实现。

既有研究中，MAC [106] 旨在为在线场景设计有效、高效的记忆适配框架，用元学习代替优化步骤。PersonalityEdit [135] 聚焦编辑 LLM 和智能体的人格，根据大五人格等理论改变其特质。MEND [134] 利用元学习思想训练轻量级模型，使其能够生成对预训练语言模型参数的修改。APP [136] 研究添加新事实是否会造成对既有事实的灾难性遗忘，重点分析邻域扰动对记忆添加的影响。KnowledgeEditor [133] 将记忆注入表述为“学习更新”问题，并训练超网络来预测模型参数的修改。Wang 等人 [137] 提出新的优化目标，改变 LLM 中的有害知识，同时维持整体性能。对基于 LLM 的智能体而言，通过知识编辑改变不良记忆，也可视为一种遗忘机制。

知识编辑为更新 LLM 参数中存储的信息提供了创新方法。通过精确定位并调整事实，这些方法可确保更新时非目标知识不受影响，从而缓解灾难性遗忘。定向调整机制还能实现更高效、资源消耗更低的更新，使知识编辑成为高精度、实时修改的有吸引力选择。然而，尽管已有可喜进展，元训练的计算成本以及如何保护无关记忆仍是重要挑战。

#### 5.2.3 文本记忆与参数记忆的优缺点

文本记忆和参数记忆各有优缺点，分别适合不同的记忆内容和应用场景。本节从多个方面比较这两种记忆形式。

**有效性。** 文本记忆存储智能体-环境交互的原始信息，更完整、更细致，但受到 LLM 提示的词元限制，智能体难以存储大量信息。参数记忆不受提示长度限制，但在把文本转化为参数时可能发生信息丢失，复杂的记忆训练也会带来额外挑战。

**效率。** 对文本记忆而言，每次 LLM 推理都需要把记忆整合进上下文提示，导致成本更高、处理时间更长。参数记忆可将信息整合进 LLM 参数，省去这些上下文的额外成本。但参数记忆在写入过程中需要额外开销，而文本记忆较易写入，尤其适合少量数据。概括而言，文本记忆写入效率更高，参数记忆读取效率更高。

**可解释性。** 文本记忆通常比参数记忆更易解释，因为自然语言是人类理解信息最自然、直接的方式，而参数记忆通常表示在潜在空间中。不过，这种可解释性以牺牲信息密度为代价：文本记忆中的词序列位于离散空间，其密度不如参数记忆的连续空间。

总之，两类记忆之间的权衡使其分别适合不同应用。例如，需要回忆近期交互的对话任务和上下文特定任务更适合文本记忆；需要大量记忆或成熟稳定知识的任务，则可能更适合参数记忆。

### 5.3 记忆操作

本文将完整的记忆过程划分为三种操作：记忆写入、记忆管理和记忆读取。三者通常相互协作，实现记忆功能并为 LLM 推理提供信息。表 3 汇总了既有工作的记忆操作。

#### 5.3.1 记忆写入

智能体感知信息后，会通过记忆写入操作存储其中一部分，以供后续使用；识别哪些信息值得存储至关重要。许多研究选择存储原始信息，也有研究把原始信息的摘要写入记忆模块。

**代表性研究。** 在 TiM [97] 中，原始信息被抽取为两个实体之间的关系，并存入结构化数据库；写入数据库时，相似内容存储在同一组中。SCM [98] 设计记忆控制器来决定何时执行操作，该控制器为整个记忆模块提供指导。MemGPT [100] 中的记忆写入完全由智能体自主控制，智能体可根据上下文自行更新记忆。MemoChat [94] 通过抽象每个对话片段讨论的主要主题来总结片段，并将主题保存为索引记忆片段的键。

**讨论。** 既有研究表明，在记忆写入期间设计信息抽取策略至关重要 [94]，因为原始信息通常冗长且含有噪声。此外，不同环境可能提供形式各异的反馈，如何提取这些信息并把它们表示为记忆，也是记忆写入中的重要问题。

#### 5.3.2 记忆管理

对人类而言，记忆信息会在大脑中不断被处理和抽象。智能体的记忆也可通过以下方式管理：借助反思生成更高层记忆，合并冗余记忆条目，以及遗忘不重要或较早的记忆。

**代表性研究。** 在 MemoryBank [6] 中，智能体对对话进行处理和提炼，形成日常事件的高层摘要，这类似于人类回忆经历中的关键部分。经过长期交互，智能体持续评估并完善知识，每日生成关于人格特质的洞见。Voyager [99] 中的智能体可根据环境反馈完善记忆。Generative Agents [83] 中的智能体可通过反思获得更高层信息，即由智能体生成抽象思考；当积累了足够多、值得处理的事件时，反思过程会被激活。GITM [93] 为建立适用于不同情形的通用参考计划，会在记忆模块中进一步总结多个计划的关键行动。

**讨论。** 大多数记忆管理操作都受到人脑工作机制的启发。借助 LLM 模拟人类心智的强大能力，这些操作可以帮助智能体更好地生成高层信息并与环境交互。

#### 5.3.3 记忆读取

当智能体需要信息进行推理和决策时，记忆读取操作会从记忆中提取相关信息。因此，如何访问与当前状态相关的信息十分重要。记忆实体数量庞大，且并非所有实体都与当前状态有关，因而需要精心设计，依据相关性和其他面向任务的因素提取有用信息。

**代表性研究。** 在 ChatDB [96] 中，记忆读取操作由 SQL 语句执行；智能体预先生成一系列 SQL 语句，形成记忆链（Chain-of-Memory）。MPC [101] 中的智能体可从记忆池检索相关记忆，该方法还提出通过思维链示例来忽略某些记忆。ExpeL [82] 使用 FAISS [124] 向量存储作为记忆池，获得与当前任务相似度分数最高的前 $K$ 条成功轨迹。

**讨论。** 记忆读取和写入在某种程度上相互协作，写入形式会显著影响读取方法。对文本形式的记忆，大多数既有工作使用文本相似度和其他辅助信息进行读取；对参数形式的记忆，现有模型可能只用更新后的参数进行推理，这可视为一种隐式读取过程。

## 6 如何评估基于 LLM 的智能体记忆

如何有效评估记忆模块仍是一个开放问题。既有工作针对不同应用提出了多样的评估策略。为清晰呈现不同方法的共通思想，本节总结一个一般框架，包含两大类评估策略（见图 5）：

1. **直接评估：** 把记忆模块作为独立组件，单独衡量其能力。
2. **间接评估：** 通过端到端智能体任务评估记忆模块；如果智能体能有效完成任务，就说明记忆模块有用。

### 6.1 直接评估

此类方法把智能体记忆视为独立组件，单独评估其有效性。既有研究可分为两类：主观评估和客观评估。主观评估根据人类判断衡量记忆有效性，可广泛用于缺少客观真值的场景；客观评估则依据数值指标评估记忆有效性，便于比较不同记忆模块。

#### 6.1.1 主观评估

主观评估有两个关键问题：（1）应评估哪些方面；（2）如何实施评估。首先，下面两个方面最常被用于评估记忆模块。

**连贯性。** 指被召回的记忆对当前上下文而言是否自然、合适。例如，如果智能体正在为 Alice 制订旅行计划，记忆就应与她的旅行偏好相关，而不是与工作偏好相关。在既有工作中，Modarressi 等人 [7] 研究记忆模块能否在不断变化的知识中提供恰当参考；Liang 等人 [98] 给出示例，展示当前查询与历史记忆的关系；Zhong 等人 [6] 和 Liu 等人 [97] 通过评分标签评估整合了上下文和检索记忆的回复之连贯性；Lee 等人 [101] 则关注召回记忆与上下文之间的矛盾。

**合理性。** 旨在评估召回的记忆是否合理。例如，若要求智能体回答“颐和园在哪里”，召回的记忆应是“颐和园在北京”，而不是“颐和园在月球上”。Lee 等人 [101] 让众包工作者直接为检索记忆的合理性评分；Zhong 等人 [6] 和 Liu 等人 [97] 招募人类评估者，检查记忆是否包含当前问题的合理答案。

至于如何实施评估，有两个重要问题。第一，如何选择人类评估者。一般而言，评估者应熟悉评估任务，以保证标注结果具有说服力和可靠性；评估者的背景还应具有多样性，以减少特定人群的主观偏差。第二，如何标注记忆模块的输出。通常可以直接为结果打分 [6]，也可以在两个候选结果之间进行比较 [95]。前者得到绝对、量化的评估结果；后者可减少分别为每个候选结果独立评分时的标注噪声。评分粒度也需要谨慎设计：过于粗略可能无法有效区分不同记忆模块的能力，过于细致则会加重评估者的判断负担。

总体而言，主观评估适用场景广泛，只需定义评估方面并让招募的工作者作出判断。由于工作者可以给出判断理由，此方法通常更具可解释性。但主观评估需要雇用人类评估者，成本较高；不同评估群体还可能具有不同偏差，使结果难以复现和比较。

#### 6.1.2 客观评估

在客观评估中，既有工作通常定义数值指标来评估记忆模块的有效性与效率。

**结果正确性。** 该指标衡量智能体能否直接根据记忆模块成功回答预先定义的问题。例如，问题可以是“Alice 今天去了哪里？”，备选答案为“A：颐和园”和“B：长城”。智能体应根据问题和记忆选出正确答案，再将其生成的答案与真值比较。正确率可形式化为：

$$
\operatorname{Correctness}=\frac{1}{N}\sum_{i=1}^{N}\mathbb{I}[a_i=\hat{a}_i],
$$

其中，$N$ 为问题数，$a_i$ 表示第 $i$ 个问题的真值答案，$\hat{a}_i$ 表示智能体给出的答案，$\mathbb{I}[a_i=\hat{a}_i]$ 是匹配函数：

$$
\mathbb{I}[a_i=\hat{a}_i]=
\begin{cases}
1, & a_i=\hat{a}_i,\\
0, & a_i\ne\hat{a}_i.
\end{cases}
$$

在既有工作中，Hu 等人 [96] 根据过去历史构建带真值标注的问题，并计算召回记忆能否匹配正确答案的准确率。类似地，Packer 等人 [100] 生成只能从过去会话中推导出的问答，再把智能体回复与真值比较来计算准确率。

**参考准确性。** 该指标评估智能体能否发现与回答问题相关的记忆内容。它不同于关注最终结果的上述指标，更关注支持智能体最终决策的中间信息，具体做法是把检索到的记忆与预先准备的真值比较。对上述“今天 Alice 去了哪里？”的问题，若记忆内容包括（A）“Alice 今天在王府井与朋友共进午餐”和（B）“Alice 午餐吃了烤鸭”，更好的记忆模块应选择（A）作为答题参考。

研究者通常用 F1 分数评估参考准确性：

$$
F1=2\cdot\frac{\operatorname{Precision}\cdot\operatorname{Recall}}{\operatorname{Precision}+\operatorname{Recall}},
$$

其中：

$$
\operatorname{Precision}=\frac{TP}{TP+FP},\qquad
\operatorname{Recall}=\frac{TP}{TP+FN}.
$$

$TP$ 表示真正例记忆内容的数量，$FP$ 表示假正例记忆内容的数量，$FN$ 表示假负例记忆内容的数量。Lu 等人 [94] 使用 F1 分数评估记忆检索过程；Zhong 等人 [6] 则着重评估能否成功检索相关记忆。

结果正确性和参考准确性都用于评估记忆模块的有效性。除有效性外，效率对现实应用也十分重要，因此还需进行如下评估。

**时间与硬件成本。** 总时间成本包括记忆适配和推理所用时间。适配时间指记忆写入与记忆管理的耗时，推理时间指记忆读取的延迟。具体而言，一项记忆操作从结束时间到开始时间之差，可视为时间消耗。每类操作的平均耗时为：

$$
\Delta \operatorname{time}=\frac{1}{M}\sum_{i=1}^{M}(t_i^{\mathrm{end}}-t_i^{\mathrm{start}}),
$$

其中 $M$ 为此类操作的次数，$t_i^{\mathrm{end}}$ 为第 $i$ 次操作的结束时间，$t_i^{\mathrm{start}}$ 为其开始时间。计算开销可通过 GPU 显存分配峰值评估。Tack 等人 [106] 使用显存分配峰值和适配时间评估记忆操作的效率。

客观评估提供了比较不同记忆方法的数值策略，这对建立该领域的基准并推动后续发展十分重要。

### 6.2 间接评估

除直接评估记忆模块外，通过任务完成情况进行评估也是一种常见策略。其直觉是：如果智能体能成功完成一个高度依赖记忆的任务，便说明所设计的记忆模块有效。下面介绍几类用于间接评估记忆模块的代表性任务。

#### 6.2.1 对话

与人类对话是智能体最重要的应用之一，记忆在其中发挥关键作用。通过在记忆中存储上下文信息，智能体可让用户获得个性化对话体验，从而提高用户满意度。因此，当智能体的其他部分确定后，对话任务的表现可以反映不同记忆模块的有效性。

在对话场景中，一致性和参与度是评估智能体记忆有效性的两种常见方法。一致性指智能体回复与上下文的一致程度，因为对话过程中应避免剧烈变化。例如，Lu 等人 [94] 在交互式对话中评估智能体的一致性，用 GPT-4 为智能体回复评分。参与度指用户愿意继续对话的程度，反映智能体回复的质量与吸引力，以及智能体为当前对话塑造角色设定的能力。Lee 等人 [101] 用 SCE-p 分数评估回复的吸引力，Packer 等人 [100] 则用 CSIM 分数评估记忆对提高用户参与度的作用。

#### 6.2.2 多源问答

多源问答可全面评估来自多种来源的记忆信息，包括试次内信息、跨试次信息和外部知识，重点考察如何整合并利用不同内容和来源的记忆。

在既有工作中，Yao 等人 [104] 评估整合了任务试次信息与 Wikipedia 外部知识的记忆。Shinn 等人 [5] 和 Yao 等人 [103] 进一步纳入同一任务的跨试次信息，使记忆可以从此前失败的试次中获得更多经验。Packer 等人 [100] 则允许智能体在问答中使用来自多个文档的信息作为记忆。

多源问答任务可检验智能体记忆整合不同来源内容的能力，也能揭示多信息源造成的记忆矛盾以及知识更新问题，这些问题都可能影响记忆模块的表现。

#### 6.2.3 长上下文应用

除上述通用应用外，基于 LLM 的智能体在许多场景中必须根据极长的提示作出决策。在这些场景中，长提示通常被视为记忆内容，在驱动智能体行为方面发挥重要作用。

Huang 等人 [19] 对长上下文 LLM 进行全面综述，并总结长上下文场景下的评估指标。Shaham 等人 [138] 提出零样本基准，评估智能体对长上下文自然语言的理解。具体任务中，长上下文段落检索是评估智能体长上下文能力的一项重要任务，要求智能体从长上下文中找出与给定问题或描述对应的正确段落 [139]。长上下文摘要是另一项代表性任务，要求智能体形成对整个上下文的全局理解，再根据描述生成摘要；可以用 ROUGE 等匹配指标将结果与真值比较。

对长上下文应用的评估提供了更广泛的方法，从实际下游场景出发评估智能体中的记忆功能。综合基准 [138, 140] 还为长上下文理解能力提供了客观评估。

#### 6.2.4 其他任务

除上述三类主要的间接评估任务外，通用任务中还有一些其他指标可以反映记忆模块的有效性。

**成功率**指智能体成功解决的任务比例。Yao 等人 [104]、Shinn 等人 [5] 和 Zhao 等人 [82] 评估智能体通过推理和记忆，能够在 ALFWorld [141] 中正确完成多少空间任务。Zhu 等人 [93] 评估智能体在 Minecraft 中制作不同物品的成功率，以展示记忆的作用。Shinn 等人 [5] 衡量生成代码通过题目的成功率；Zheng 等人 [91] 计算计算机控制的成功率和元素选择的准确率，以说明“轨迹作为示例”记忆的作用。

**探索程度**通常用于探索类游戏，反映智能体探索环境的广度。例如，Wang 等人 [99] 比较智能体在 Minecraft 中探索到的不同物品数量，以反映记忆中的技能学习情况。

事实上，几乎所有配备记忆的智能体都可以通过消融研究评估记忆效果，即比较有无记忆模块时的表现。特定场景下的评估能够更实际地反映记忆对下游应用的重要性。

### 6.3 讨论

与直接评估相比，通过具体任务进行间接评估更容易实施，因为已有许多公开基准。但任务表现可能由多种因素共同决定，记忆只是其中之一，因此评估结果可能存在偏差。直接评估可独立衡量记忆模块的有效性，提高评估结果的可靠性。然而，据作者所知，当时尚无专门面向基于 LLM 的智能体记忆模块的开源基准。

### 7.1 角色扮演与社会模拟

角色扮演是基于 LLM 的智能体的一项经典应用，记忆在智能体内部发挥关键作用。它赋予不同角色各自鲜明的特征，使角色彼此区分。许多既有研究探索了构建角色记忆的方法 [105, 143, 145-147]。

Shao 等人 [105] 通过“经历上传”构建角色记忆，即使用监督微调把记忆注入模型参数。Li 等人 [143] 用改进的提示以及从剧本中提取的角色记忆增强大语言模型的角色扮演能力，把用户查询和聊天机器人的回复拼接为记忆序列。Wang 等人 [145] 将角色专门知识和情节记忆注入基于 LLM 的智能体，其中把上下文问答对拼接成情节记忆。Zhao 等人 [146] 旨在根据叙事中提取的人格特质引导智能体生成类似人类的回复，这些人格特质可被存储，并按照相关性和重要性检索。Zhou 等人 [147] 为不同角色生成基于人物的对话，再通过监督微调使基于 LLM 的智能体获得相应风格。

社会模拟本质上是角色扮演的扩展，更关注多智能体建模。记忆模块是此类应用的重要组件，有助于准确模拟人类的动态行为。Kaiya 等人 [148] 提出“总结并遗忘”（Summarize-and-Forget）记忆机制，使智能体在社会场景中更好地进行自我监控。Gao 等人 [2] 关注社交网络模拟系统，系统中每个智能体都拥有一个记忆池，由在线平台上的多样化用户消息组成，用来识别用户。Li 等人 [163] 保存对话上下文，其中包括经济环境和智能体此前数月的决策，从而模拟宏观经济趋势对智能体决策的影响，并使其把握市场动态。Li 等人 [109] 模拟人类社会中的求职场景，智能体记忆起初包含个人资料和目标，随后又以对话、个人反思等信息不断充实。Hua 等人 [150] 模拟参战国在战争中的决策和后果，并把智能体对话持续保存进记忆。

设计用于角色扮演和社会模拟的智能体记忆，可以得到几点启示。第一，记忆应与角色特征一致，可用于识别每个角色并将其与其他角色区分开；这对提高角色扮演的真实感与社会模拟的多样性至关重要。第二，记忆应恰当地影响智能体的后续行动，以确保行为的一致性和合理性。此外，类人智能体的记忆机制应符合人类记忆特征，例如遗忘以及长、短期记忆，并参考认知心理学理论。

### 7.2 个人助理

基于 LLM 的智能体非常适合创建个人助理，例如能与用户长期对话的智能体 [94, 101, 153]，以及自动搜索信息的智能体 [164]。这类智能体通常需要记住此前对话来维持一致性，还要记住关键风格和事件，以生成更个性化、更相关的回复。

Lu 等人 [94] 通过保存对话内容和信息来维持上下文一致性，并借助检索找到恰当的相关信息。Lee 等人 [101] 总结对话以提取重要信息，存储后供未来推理时检索。Pan 等人 [164] 关注信息搜索任务，设计记忆模块存储用户上下文信息，并通过工具使用赋予智能体外部知识。Wu 等人 [153] 把重要上下文保存为记忆，以维持对话一致性。

总之，个人助理大多采用文本形式的检索方法实现记忆，因为这类方法更擅长从对话片段中寻找相关信息。在记忆存储方面，智能体应记住用户-智能体交互中的事实信息以及用户个人风格，从而生成符合用户情境的回复。在回忆记忆时，智能体应识别并检索与当前查询和上下文相关的记忆。遵循这一原则，智能体才能正确理解用户要求并维持对话一致性。

### 7.3 开放世界游戏

在游戏与开放世界探索中，基于 LLM 的智能体通常把过去的观察保留为任务上下文，并存储此前成功试次的经验。利用过去经验，智能体可以避免重复犯同样的错误，对环境形成高层理解，从而更有效地探索。一些智能体还可访问外部数据库或 API 来获取通用知识 [93, 99, 159, 161]。

Wang 等人 [99] 在 Minecraft 中把已获得的技能保存到记忆，供后续使用。Zhu 等人 [93] 存储并检索成功轨迹，作为相似任务的示例，并通过 API 调用使用外部 Minecraft Wiki。Wang 等人 [159] 将多模态记忆构建为知识库，通过检索交互经验为提示提供示例。Yan 等人 [161] 维护用于决策的工作记忆，存储并检索相关的过往经验，同时利用外部数据集提供通用知识。

总而言之，无论试次内还是跨试次信息，记忆的关键都在于反思过去的交互，并提炼出可用于后续探索的经验。除了通过亲身参与试次积累经验外，把外部知识吸收为智能体记忆的一部分，也是增强智能体探索能力的重要方式。

### 7.4 代码生成

在代码生成场景中，基于 LLM 的智能体可以从记忆中搜索相关信息，从而获得更多开发知识。它们可以保存过往经验以应对未来问题，也可以在对话式开发界面中维护上下文 [1, 109, 142, 144]。

Tsai 等人 [142] 构建外部非参数记忆数据库，存储编译器错误和人类专家指令，用于自动修复语法错误。GameGPT [144] 将个人信息存入记忆，帮助智能体保留用于决策的上下文与知识。Qian 等人 [1] 使用多智能体开发软件，每个角色都维护一份记忆，用于存储与其他角色的过往对话。Li 等人 [109] 同样关注软件开发，当出现错误时，智能体可检索保存在记忆中的历史记录。Zhang 等人 [114] 则让智能体在遇到代码生成问题时搜索相关信息。

智能体可以利用外部资源学习代码相关知识并存入记忆，从而增强代码生成能力。记忆还能提高代码生成的连续性和一致性：通过整合上下文记忆，智能体可以更好地理解软件开发需求，使生成的代码更加连贯。此外，记忆对代码的迭代优化也很重要，因为智能体可根据历史信息识别开发者的目标。

### 7.5 推荐

推荐领域的一部分研究关注模拟推荐系统中的用户 [95, 108]，其中记忆可表示现实世界中的用户画像和历史；另一部分研究则试图提高推荐性能，或提供其他形式的推荐界面 [102, 149]。

Wang 等人 [95] 在推荐场景中模拟用户行为，为推荐系统生成数据；智能体把过去的观察和洞见存入分层记忆。Huang 等人 [108] 的基于 LLM 的智能体记忆，既可以长期保存用户对话历史，也可以捕捉与当前提示相关的近期对话，从而模拟交互式推荐系统；该方法还使用演员-评论家式反思来增强智能体的稳健性。文献 [149] 分别为物品智能体和用户智能体配备不同记忆：物品智能体使用动态记忆模块，捕捉并保存与自身固有属性以及采用者偏好相关的信息；用户智能体则通过自适应记忆更新机制，使智能体操作与用户行为和偏好保持一致。Wang 等人 [102] 记住评论、物品评分等个性化用户信息，并通过网络搜索工具获取领域知识和实时信息。

无论是模拟推荐系统用户还是捕捉其偏好，通过记忆保存个性化信息都不可或缺。一项关键挑战是如何把个性化信息和反馈与 LLM 对齐，并存入智能体记忆。这也是弥合传统推荐模型与 LLM 之间差距的重要任务。

### 7.6 特定领域的专家系统

**医学领域。** 既有工作大多用记忆中的外部知识赋能医学领域的基于 LLM 的智能体 [107, 115, 129, 132, 151]。Wang 等人 [107] 以问答形式使用医学知识图谱 CMeKG [165] 微调 LLaMA [127]，增强医学领域知识。Xiong 等人 [129] 采用 LoRA [131] 高效微调用于医疗的基础模型。Wang 等人 [151] 使基于 LLM 的智能体能够获取文本形式的外部知识作为推理参考。Shi 等人 [152] 则以过往经验中最相关的成功案例构建记忆，并用相似性指标检索医学领域的相关问题。

**金融领域。** 一些研究将基于 LLM 的智能体用于金融，其记忆可存储金融知识 [113]、市场信息 [154, 156] 和成功经验 [155, 157]。Yang 等人 [113] 构建金融投资数据集并微调 LLaMA [127]，赋予其投资知识。Li 等人 [154] 设计分层记忆结构，存储不同类型的市场信息。Wang 等人 [155] 记录交易和信息等正在发生的交互，以确保回复一致；同时把先前输出记录为经验，检索相关示例，为智能体提供多样化学习上下文。Koa 等人 [157] 保存过去的价格变动及其解释，并对先前试次进行反思。Yu 等人 [156] 使用分层记忆机制，为推理提供丰富信息。

**科学领域。** 一些既有工作为基于 LLM 的智能体设计包含大量知识的记忆，以解决科学问题 [158, 160, 162]。Chen 等人 [158] 把分子数据库和在线文献纳入智能体记忆的外部知识，需要相关信息时再进行检索。Zhao 等人 [160] 和 Chen 等人 [162] 分别通过在化学与结构化材料数据上进行微调，赋予智能体领域知识。

要构建特定垂直领域的智能体专家系统，必须在记忆中保存领域专门知识，但这面临几项挑战。第一，领域知识具有专业性且要求更高准确性，因而难以构建记忆存储。第二，领域知识往往有时效性，未来可能过时，因此部分知识过期时，记忆需要局部更新。第三，领域知识体量庞大，很难根据当前查询从记忆中准确召回。

### 7.7 其他应用

记忆在基于 LLM 的智能体中还有其他应用。Wang 等人 [166] 关注云服务根因分析任务，用记忆存储框架规则、任务要求、工具文档、少样本示例和智能体观察。Qiang 等人 [167] 解决本体匹配问题，智能体保存对话并构建关系数据库，用于检索外部知识。Wen 等人 [168] 研究自动驾驶，其记忆模块基于向量数据库构建，包含过往驾驶场景的经验。Wang 等人 [169] 提出改进用户验收测试的方法，采用自我反思机制；每个试次结束后，操作智能体都会总结对话并更新记忆池，直至实现当前步骤的目标。

不同应用中的记忆关注点各异，因为记忆天然服务于下游任务。因此，记忆设计也应考虑任务要求。

## 8 局限与未来方向

### 8.1 参数记忆的进一步发展

目前，基于 LLM 的智能体记忆主要采用文本形式，尤其是观察记录、试次经验和文本知识库等上下文知识。文本记忆具有可解释、易扩展和易编辑的优点，但与参数记忆相比牺牲了效率。从本质上看，参数记忆具有更高的信息密度：它在潜在空间中通过连续实数向量表达语义，而文本记忆则在离散空间中组合词元来表达语义。因此，参数记忆的表达空间更丰富，其软编码也比词元序列的硬编码形式更稳健。

此外，参数记忆的存储效率更高，无需显式存储大量文本，类似于知识压缩过程。在合并、反思等记忆管理方面，参数记忆不一定需要像文本记忆那样设计人工规则，而可以利用优化方法隐式学习这些过程。可插拔的参数记忆还类似于数字生命卡，可以赋予智能体所需特征。例如，Huatuo [107] 通过在中文医学知识库上微调 Llama [127]，增强智能体的生物医学专业能力；MAC [106] 则通过元学习代替传统优化阶段，为在线场景设计参数记忆适配框架。

参数记忆虽前景广阔，目前仍面临许多挑战，首要问题是效率：如何有效地把文本信息转化为参数或参数修改？目前，研究者可通过监督微调把大量领域知识转入 LLM 参数，但这既耗时又需要大量文本语料，不适合情境性知识。一种可行方法是用元学习让模型学会记忆。例如，MEND [134] 用元学习训练紧凑模型，使其能够生成对预训练语言模型参数的调整。参数记忆缺乏可解释性也是一项障碍，尤其是在医学等需要高度信任的领域。因此，提升参数记忆的可信性与可解释性，是亟待解决的问题。

### 8.2 基于 LLM 的多智能体应用中的记忆

对 LLM 记忆机制的探索已经扩展到多智能体系统（MAS）这一活跃领域，并在同步、通信和信息不对称管理方面取得重要进展。合作场景中的一个关键方面，是智能体之间的记忆同步。这一过程是建立统一知识库、确保不同智能体决策一致性的基础。例如，Chen 等人 [170] 强调在多机器人协作中集成同步记忆模块的重要性。

另一重要方面是智能体间通信，它高度依赖记忆来维持上下文和解释消息。例如，Mandi 等人 [171] 展示了由记忆驱动的通信框架，促进智能体形成共同理解。除合作场景外，一些研究也关注竞争场景，其中信息不对称成为关键问题 [172]。

展望未来，基于 LLM 的多智能体系统记忆发展正处于技术创新与战略应用的交汇点。研究者需要探索新型记忆模块，以进一步增强智能体同步、实现更有效的通信，并在信息丰富的环境中提供战略优势。开发此类记忆模型不仅要解决当前的记忆集成与管理挑战，也要发掘记忆在促进更稳健、智能且适应性更强的多智能体系统方面尚未利用的潜力。先驱研究表明，不断演进的基于 LLM 的多智能体系统为未来的记忆利用与管理创新提供了充满希望的舞台。这一探索有望揭示记忆集成的新维度，突破当前能力边界，并为多智能体系统建立新的基准。

### 8.3 基于记忆的终身学习

终身学习是人工智能中的前沿主题，旨在把智能体的学习能力扩展到整个生命周期 [173]。智能体可以持续与环境交互，不断观察环境并获取外部知识，从而以类似人类的方式增强自身。智能体记忆是实现终身学习的关键，因为智能体需要学会存储和应用过去的观察。

基于 LLM 的智能体终身学习具有重要的实际价值，例如用于长期社会模拟和个人助理，但也面临若干挑战。第一，终身学习具有时间性，因此智能体记忆必须捕捉时间特征；这种时间性可能引发记忆之间的相互作用，例如记忆重叠。第二，终身学习周期很长，需要存储大量记忆并在需要时检索，因而可能还需要引入某种遗忘机制。

### 8.4 类人智能体中的记忆

类人智能体指被设计为表现出与人类一致行为的智能体，从而支持社会模拟、人类行为研究和角色扮演等应用。与通常偏好能力越强越好的任务型智能体不同，类人智能体的能力水平应尽可能贴近人类。因此，类人智能体的记忆应符合人类认知过程，遵循记忆扭曲和遗忘等心理学原理。

此外，类人智能体应具有知识边界，即其知识应与所模拟实体的知识相符。例如，在角色扮演中，扮演儿童的智能体不应掌握高等数学概念或其他超出该年龄通常认知范围的复杂知识 [174]。

## 9 结论

本文系统回顾了基于 LLM 的智能体记忆机制，聚焦三个关键问题：记忆模块“是什么”“为什么需要”以及“如何设计和评估”。为展示智能体记忆的重要性，本文还介绍了许多记忆模块发挥关键作用的典型应用。作者相信，这篇综述既能为该领域的初学者提供有价值的参考，也能启发更先进的记忆机制，进一步增强基于 LLM 的智能体。
